# 66MSG

Мессенджер на React, Rust/Axum и WebSocket.

## Возможности

- регистрация нового аккаунта одноразовым кодом из Telegram-бота;
- пользователь самостоятельно выбирает публичный ник 66MSG;
- при регистрации пользователь устанавливает пароль;
- Telegram ID, username и имя сохраняются только как данные привязки;
- вход по нику и паролю;
- вход по нику и одноразовому коду, который сайт автоматически отправляет через бота;
- Telegram-уведомление о каждом входе с кнопкой отзыва конкретной сессии;
- JWT-сессия сроком на 30 дней;
- общий чат `66Polygon`;
- личные сообщения;
- постоянное хранение пользователей, кодов и переписки;

## Настройка Telegram-бота

1. Откройте `@BotFather` в Telegram.
2. Выполните `/newbot`.
3. Сохраните полученный token и username бота.
4. Скопируйте `.env.example` в `.env`.
5. Заполните:

```dotenv
JWT_SECRET=случайная-строка-не-короче-32-символов
TELEGRAM_CODE_SECRET=другая-случайная-строка-не-короче-32-символов
TELEGRAM_BOT_TOKEN=токен-от-BotFather
TELEGRAM_BOT_USERNAME=username_бота_без_собаки
```

`JWT_SECRET` и `TELEGRAM_CODE_SECRET` должны быть разными.

Бот работает через long polling. Webhook и Telegram Mini App не используются.

## Регистрация

1. Пользователь нажимает регистрацию через Telegram.
2. Сайт предлагает открыть настроенного бота.
3. Пользователь отправляет `/start` или `/register`.
4. Бот создаёт шестизначный код на 5 минут.
5. В файле данных сохраняется только HMAC-SHA256 кода, Telegram ID и профиль.
6. Пользователь вводит на сайте желаемый ник, пароль и код.
7. Backend проверяет уникальность ника, сохраняет Argon2-хеш пароля, атомарно создаёт пользователя, помечает код использованным и возвращает JWT.

Повторная выдача кода инвалидирует предыдущие активные коды этого Telegram-пользователя.

## Вход

По паролю:

1. Пользователь выбирает вкладку «Вход» → «По паролю».
2. Вводит ник и пароль.
3. Backend проверяет Argon2-хеш и возвращает JWT.

Через Telegram:

1. Пользователь вводит ник на сайте и нажимает «Получить код в Telegram».
2. Backend находит привязанный `telegramId`.
3. Бот автоматически присылает одноразовый код входа на 5 минут.
4. Пользователь вводит код на сайте.
5. Backend проверяет код и возвращает JWT.

После успешного входа бот отправляет уведомление:

`Выполнен вход в аккаунт 66MSG`

Под надписью «Если это не вы» находится кнопка «Выйти из аккаунта с этого устройства». Нажатие отзывает только сессию устройства, о входе которого пришло уведомление, и закрывает его активное WebSocket-соединение.

## API

- `GET /auth/telegram` — адрес Telegram-бота;
- `POST /auth/register/telegram-code` — регистрация по нику, паролю и Telegram-коду;
- `POST /auth/login/password` — вход по нику и паролю;
- `POST /auth/login/telegram-code/request` — автоматическая отправка кода на привязанный Telegram;
- `POST /auth/login/telegram-code` — вход по нику и Telegram-коду;
- `GET /ws?token=JWT` — сообщения и список пользователей.

Ошибки Telegram-регистрации:

- `INVALID_CODE`;
- `CODE_EXPIRED`;
- `TOO_MANY_ATTEMPTS`;
- `TELEGRAM_ALREADY_REGISTERED`.
- `USERNAME_TAKEN`.

## Безопасность

- `codeHash = HMAC_SHA256(code + ":" + telegramId, TELEGRAM_CODE_SECRET)`;
- отдельный HMAC lookup-hash позволяет найти запись по введённому коду, не сохраняя код открыто;
- сравнение HMAC выполняется в постоянном времени;
- пароли хранятся только как Argon2-хеши с уникальной солью;
- коды регистрации и входа имеют разные назначения и не взаимозаменяемы;
- каждый JWT связан с серверной сессией и может быть отозван кнопкой в Telegram;
- код одноразовый и действует 5 минут;
- максимум 5 запросов проверки с одного IP за 5 минут;
- реальные коды не записываются в серверные логи;
- создание пользователя и использование кода сохраняются одной операцией под блокировкой данных;
- query-параметр JWT исключён из HTTP-логов.
